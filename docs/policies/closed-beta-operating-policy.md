# Política operacional do beta fechado

Versão: 1.0  
Status: adotada para o beta fechado inicial

## Decisões adotadas

| Tema | Decisão |
|---|---|
| Operador inicial | az1nn / Mememom |
| Escopo de lançamento | beta fechado; não é lançamento público de UGC/online |
| Retenção | logs operacionais e denúncias: até 90 dias, salvo necessidade de segurança/obrigação aplicável |
| Moderação | moderador e administrador; administrador decide escalonamento/recursos |
| Canon | rotação semestral; suspensão emergencial por segurança ou direitos |
| Online | conta por e-mail, servidor autoritativo, WebSocket, região inicial Brasil |
| Código | MIT; contribuições assinadas por DCO |
| Conteúdo | separado da licença de código; exige declaração de origem/direitos |

## Regras de segurança

- Sandbox é privado e não competitivo.
- Conteúdo não é público nem Canon automaticamente.
- Uma aprovação de moderação é apenas elegibilidade; MM-08 cria a edição imutável e a legalidade de formato.
- O operador pode suspender imediatamente uma edição ou submissão por suspeita de direitos, segurança ou abuso, preservando o registro de auditoria.

## Contatos e condição para abertura pública

O contato privado do beta é fornecido pelo operador aos participantes. Antes de abrir UGC ou partidas online ao público, o projeto deve habilitar o relatório privado de vulnerabilidades do GitHub e publicar um contato verificável de moderação/privacidade. Esta política não cria um endereço de e-mail inexistente.

## Apelação

Criadores podem pedir revisão de uma decisão de moderação pelo canal privado do beta. Um administrador diferente do decisor inicial deve revisar o caso quando houver disponibilidade; a decisão e a justificativa categorizada entram no histórico de auditoria.
