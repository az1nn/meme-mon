# MM-10 — Open Source Governance

Status: IN REVIEW — closed-beta policy artifacts are adopted; public contact and asset-license gates remain.  
Depends on: V1 public/community scope  
Unlocks: V1 release candidate

## User value

Contributors, creators, moderators and players have clear rules for contributing code, submitting content, reporting abuse/security concerns and understanding what is—and is not—licensed by the project.

## Functional requirements

**FR-01 Code governance.** Adopt an OSI-approved code license, contribution mechanism (CLA or DCO), maintainership/decision process and code-of-conduct enforcement path.

**FR-02 Content separation.** Publish a distinct policy for first-party assets and user content. Repository code rights must never imply permission to upload, reuse or publish third-party meme media.

**FR-03 Card review.** Define submission review criteria, conflicts/recusal, moderation roles, appeal/contact route and how MM-07/MM-08 decisions are recorded.

**FR-04 Security and privacy.** Publish a private security-reporting route, disclosure expectation, service/privacy contact and incident ownership before online/public UGC release.

**FR-05 Release accountability.** A V1 release checklist names the responsible maintainers/operators and links exact policy versions, build evidence and supported-target acceptance evidence.

## Acceptance scenarios

1. A new code contributor can identify the license and contribution agreement before submitting work.
2. A content creator can identify the difference between code licensing, asset licensing and their own media rights.
3. A report or security disclosure has a defined non-public route and responsible owner.
4. Moderation/Canon decisions link to policy/version evidence without exposing unnecessary private data.
5. A release candidate cannot claim public UGC/online readiness without adopted policy artifacts and named owners.

## Decisões operacionais adotadas

- Código MIT e DCO; ativos de primeira parte e conteúdo de usuários permanecem domínios separados.
- O operador inicial é az1nn / Mememom; moderação usa moderador + administrador e apelação privada no beta.
- Contatos públicos verificáveis de segurança/moderação/privacidade e compromisso de plataformas são gates antes da abertura pública.

## Non-goals

Legal advice, guaranteed rights clearance, paid legal review, commercial terms, trademark registration or automated moderation.
